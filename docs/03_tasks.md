# タスク一覧

1タスク = implementer が1回で実装し、reviewer が1回で判定できる大きさ。
各タスクに **完了条件** を書く。reviewer はこれを基準に PASS / FAIL を判定する。
PASS になったタスクだけ `[x]` にする。FAIL は指摘を添えて implementer に差し戻す。

## ステップ 1: 事実を記録できる

- [x] **1-1 Supabase 接続と認証**
  - Supabase クライアント（ブラウザ用・サーバー用）を `src/lib/supabase/` に置く
  - ログイン画面（メール＋パスワード）。Sign Up の導線は作らない
  - 未ログインなら `/login` にリダイレクト
  - ログイン後、`profiles` から自分の組織を取得して表示できる
  - 完了条件:
    1. 未ログインで `/` を開くと `/login` に遷移する
    2. 正しいメール・パスワードでログインすると `/` に遷移し、組織名が表示される
    3. 誤ったパスワードではエラーが表示され、遷移しない
    4. 画面のどこにも Sign Up の導線がない
    5. E2E はテスト用アカウント A（環境変数 `E2E_EMAIL` / `E2E_PASSWORD`）でログインでき、組織名「テスト農園A」が表示される
    6. 組織の分離: B（`E2E_B_EMAIL` / `E2E_B_PASSWORD`）でログインすると「テスト農園B」が表示され、A の組織のデータ（例: `fields` を直接クエリ）が 0 件である

- [x] **1-2 圃場の登録と一覧**
  - 圃場の一覧、新規登録（名前・圃場記号・代表点）。代表点は緯度経度の入力（地図タップは 1-3 で追加）
  - 完了条件:
    1. 圃場を登録すると一覧に表示される
    2. 名前が空、または代表点が未指定なら登録できず、理由が表示される
    3. 同じ組織内で同じ名前の圃場は登録できない

- [x] **1-3 圃場マップと株の一括配置**
  - MapLibre ＋ 地理院タイル（空中写真、出典表示あり）で圃場を表示
  - 最初の株の位置と列の向きをタップで指定し、「列数 × 本数」で株間 3m の格子を生成
  - 生成した株は確定前にドラッグで位置を直せる。確定で `mats` に保存
  - 株コードは `圃場記号-3桁ゼロ埋め連番`（例 `A-001`）。連番はその圃場の既存の最大番号の次から
  - 生成時に1回入力する: 品種（既定: ドワーフナムワ）、植え付け日（既定: 今日）、苗の種類（組織培養 / 購入吸芽）
  - 格子の生成と距離計算は `src/lib/geo.ts`（単体テスト対象）
  - 完了条件:
    1. 地図に航空写真と出典（地理院タイル）が表示される
    2. 2列 × 3本で生成すると、6株が約 3m 間隔（2.5〜3.5m）で表示される
    3. 確定すると 6株が保存され、再読み込み後も表示される。株コードが `A-001`〜`A-006` のように連番になっている（既に株がある圃場では、その続きの番号）
    4. 株を1つドラッグしてから確定すると、動かした位置で保存される
    5. 保存された株に、入力した品種・植え付け日・苗の種類が入っている

- [x] **1-4 株の個別追加と株の詳細**
  - 地図の空いている位置をタップして株を1つ追加（品種の既定値は、その圃場で最後に登録した株の品種）
  - 株をタップすると株の詳細（コード、品種、植え付け日、茎の一覧）が開く
  - 完了条件:
    1. 株を1つ追加でき、地図と詳細に反映される
    2. 株の詳細に、その株の茎が世代順に表示される（茎がなければ「茎なし」）

- [x] **1-5 茎の登録（植え付け）**
  - 株の詳細から、最初の茎（generation=1）を登録: 苗の種類（組織培養/吸芽）、植え付け日、初期葉数
  - 植え付け時は `status=active`、`adopted_at=planted_at`
  - 株ごとに active な茎は最大3本（DB トリガー）。超えた場合はエラーを画面に出す
  - 完了条件:
    1. 茎を登録すると株の詳細に表示され、累計葉数 = 初期葉数 になっている
    2. 4本目の active な茎を登録しようとするとエラーが表示され、登録されない

- [x] **1-6 茎の記録入力（葉数）**
  - 茎の画面で `leaves_new`（+0 / +1 / +2 ボタン）、`leaves_current`、`leaves_removed`（枯葉処理）を記録
  - 記録はオンライン時に即保存。累計葉数が更新される
  - 完了条件:
    1. +1 を押すと累計葉数が 1 増え、再読み込み後も保持される
    2. 枯葉処理を 2 枚で記録すると、イベントとして保存され履歴に出る
    3. 記録を削除・編集する UI がない

- [ ] **1-7 写真の撮影と保存**
  - 茎の画面から写真を撮影（`<input type="file" capture>`）し、Supabase Storage に保存。`photos` に行を作る（`target_type=stem`、EXIF の撮影日時）
  - 完了条件:
    1. 画像を選ぶと Storage に保存され、茎の履歴にサムネイルが出る
    2. `photos` の行に `target_id` と `taken_at` が入っている

- [ ] **1-8 イベントの記録（出蕾・袋掛け・収穫・被害）**
  - 出蕾（生葉数・周囲長）、段数、袋掛け、摘蕾、収穫（重量）、被害（種類・程度）
  - 出蕾で `stems.status=flowered`、収穫で `harvested` に更新。収穫後は茎の記録入力を閉じる
  - 完了条件:
    1. 出蕾を記録すると茎の状態が「出蕾済み」になり、その時点の累計葉数がイベントに保存される
    2. 収穫を記録すると状態が「収穫済み」になり、その茎には記録ボタンが出ない
    3. 被害を「喪失」で記録すると状態が「喪失」になる

- [ ] **1-9 オフライン保存と同期**
  - 観測・イベント・写真を IndexedDB に保存し、オンライン復帰時に同期。未同期件数を常に表示
  - 完了条件:
    1. オフライン（Playwright の `context.setOffline(true)`）で +1 を記録すると、未同期件数が 1 になる
    2. オンラインに戻すと同期され、未同期件数が 0 になり、サーバーに記録が存在する
    3. オフラインで記録した写真も同様に同期される

- [ ] **1-10 PWA とアクセス制限**
  - manifest、Service Worker、ホーム画面追加のための設定。Cloudflare Access の設定手順を `docs/` に書く
  - 完了条件:
    1. Lighthouse の PWA 項目（installable）が通る
    2. オフラインでアプリの殻（シェル）が開く
